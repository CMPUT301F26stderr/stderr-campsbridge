**Test case 就是“用代码自动检查功能是否符合预期”的测试用例。** 它会准备输入、执行操作，再检查结果。

例如，你的 #41 有这样一个测试：

```text
输入：报名 09:00–10:00，预订 10:00–11:00
预期：Valid
实际运行校验函数 → 比较实际结果和预期
```

相同就通过，不相同就失败。以后别人改代码、破坏了这个规则，测试就能发现。

我看了当前 `main`，你们仓库主要有下面几类测试。

**1. 业务规则和模型测试：检查“算得对不对、规则对不对”。**

| 实际测试文件 | 检查什么 |
|---|---|

| `StayTest.kt` | 入住到退房之间包含哪些住宿夜晚 |
| `GuestCapacityMatchTest.kt` | 营地容量是否满足人数要求 |
| `CampsiteTextMatchTest.kt` | 搜索文字是否匹配营地信息 |
| `CampsiteOrderingTest.kt` | 营地是否按规定排序 |
| `OptionalContactInputTest.kt` | 可选邮箱和电话输入是否正确 |
| `PriceInputTest.kt` | 价格输入是否按约定解析 |

这些测试通常可以直接在电脑上运行，无需启动 Android 手机模拟器。

你的 [LotteryWindowInputTest.kt](https://github.com/CMPUT301F26stderr/stderr-campsbridge/blob/5282afb1424a30bac10ec4d79296ca1037e7a31d/app/src/test/java/io/github/CMPUT301F26stderr/campsbridge/ui/lotteries/logic/LotteryWindowInputTest.kt) 有 **12 个测试方法**，检查的情况包括：

- 预订与报名重叠。

- 同时有多个问题时，是否返回规定的第一个错误。

**非法输入也需要测试。** 例如，错误时间返回 `InvalidRegistration`，这条测试就应该通过，因为程序正确识别了错误。

```text

```

例如，[BookingRepositoryTest.kt](https://github.com/CMPUT301F26stderr/stderr-campsbridge/blob/5282afb1424a30bac10ec4d79296ca1037e7a31d/app/src/test/java/io/github/CMPUT301F26stderr/campsbridge/integration/firebase/booking/BookingRepositoryTest.kt) 检查：

这些测试使用本地 Firebase Emulator 测试环境。它与运行 Android App 的手机模拟器是两种不同的东西。


**5. 开发脚本测试：检查“团队的自动化工具有没有写错”。**

例如：

- `test_check_hooks.py`：检查提交检查脚本。

它们帮助保证构建、检查和发布流程可靠。

**一个测试文件通常包含很多 test cases。**

以你的文件为例：

```text
LotteryWindowInputTest.kt   ← 测试文件
    adjacentWindowsAreValid()   ← 一条测试用例
        assertEquals(...)      ← 判断预期与实际是否相同
```

`@Test` 标记的函数通常就是一条测试用例；一个用例里可以有多个 `assert`，检查多个相关结果。

`Fixture`、`TestAppHost`、`MainDispatcherRule` 等文件则提供测试数据或运行环境，供这些用例使用。

**运行方式也分开了：**

| 想检查什么 | 方式 |
|---|---|
| 只检查你的 H07 | `bash ./gradlew :app:testDebugUnitTest --tests '*LotteryWindowInputTest'` |
| 普通本地测试 | `bash ./gradlew :app:testDebugUnitTest` |
| Lint、本地测试和 APK 构建 | `bash scripts/check.sh` |
| Firebase 集成与权限测试 | `bash scripts/check-firebase.sh` |
| Android UI 测试 | 启动设备后，在 Android Studio 运行对应测试 |

特别注意，**普通的 `testDebugUnitTest` 在你们配置中会排除 Firebase 集成测试**，所以“本地单元测试全部通过”和“所有类别的测试全部通过”代表不同的验证范围。

你们给 H 系列任务预先准备测试，就是先把函数的要求变成可运行的检查：你实现函数后跑这些测试，可以确认正常情况、边界情况和错误情况是否都符合约定。
